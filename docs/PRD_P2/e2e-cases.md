# GCP P2 — e2e 테스트 케이스 (E2E Cases)

## 1. 개요

| 항목 | 내용 |
|------|------|
| 테스트 도구 | Playwright |
| 대상 | 인증 흐름 + 핵심 사용자 시나리오 |
| 실행 환경 | localhost:5173 (프론트) + localhost:3000 (백엔드) |

## 2. 테스트 케이스 목록

### TC-01. 회원가입 → 로그인 → 강의 결제 흐름 (학생)

```
시나리오: 신규 학생이 회원가입 후 강의를 결제한다.

1. /register 접속
2. 역할 "학생" 선택
3. 이메일, 닉네임, 비밀번호 입력 후 회원가입
4. /login 이동 → 방금 만든 계정으로 로그인
5. JWT 토큰이 localStorage에 저장되는지 확인
6. /lectures 이동 → 강의 카드 클릭
7. 강의 상세 페이지에서 "💳 바로 결제하기" 클릭
8. /checkout 이동 확인
9. 결제 수단 선택 → 약관 동의 → "결제하기" 클릭
10. 결제 완료 화면 표시 확인
11. "내 수강 목록" 클릭 → /mypage 이동
12. 수강 중 상태로 강의가 표시되는지 확인

기대 결과:
- 각 단계 정상 이동
- 결제 후 applications 테이블에 status='approved' 행 생성
- 마이페이지에 수강 중 강의 표시
```

### TC-02. 비로그인 사용자 보호 라우트 접근 차단

```
시나리오: 비로그인 상태에서 보호된 페이지에 접근하면 /login으로 이동한다.

1. 로그아웃 상태 확인
2. /mypage 직접 접속 → /login 리다이렉트 확인
3. /cart 직접 접속 → /login 리다이렉트 확인
4. /growth 직접 접속 → /login 리다이렉트 확인
5. /coach/dashboard 직접 접속 → /login 리다이렉트 확인

기대 결과:
- 모든 보호 경로에서 /login으로 리다이렉트
```

---

### TC-03. 학생이 코치 전용 페이지 접근 차단

```
시나리오: 학생 계정으로 로그인 후 코치 전용 페이지 접근 시 / 로 이동한다.

1. 학생 계정으로 로그인
2. /coach/dashboard 직접 접속 → / 리다이렉트 확인
3. /coach/lecture/new 직접 접속 → / 리다이렉트 확인

기대 결과:
- 코치 전용 경로에서 / 로 리다이렉트
```

---

### TC-04. 장바구니 담기 → 결제 흐름

```
시나리오: 학생이 장바구니에 강의를 담고 결제한다.

1. 학생 계정으로 로그인
2. 강의 상세 페이지에서 "🛒 장바구니에 담기" 클릭
3. Navbar 장바구니 아이콘에 수량 뱃지(1) 표시 확인
4. /cart 이동 → 담긴 강의 확인
5. "💳 결제하기" 클릭 → /checkout 이동
6. 결제 완료 후 장바구니에서 해당 강의 제거 확인

기대 결과:
- 장바구니 담기/제거 정상 동작
- 결제 후 cart_items에서 해당 행 제거
```

### TC-05. 코치 강의 등록 → 수강자 확인 흐름

```
시나리오: 코치가 강의를 등록하고 수강자 목록을 확인한다.

1. 코치 계정으로 로그인
2. /coach/lecture/new 이동 → 강의 정보 입력 후 등록
3. /coach/dashboard 이동 → 내 강의 목록 탭 확인
4. 등록한 강의가 목록에 표시되는지 확인
5. "수강자 보기" 클릭 → 수강자 목록 표시 확인

기대 결과:
- 강의 등록 후 목록에 표시
- coach_id가 JWT에서 자동 추출되어 본인 강의만 표시
```
